# Alexa Smart Home Plus

Alexa に登録済みの機器を選び、Apple のホームアプリへ橋渡しする Homebridge プラグインです。Homebridge 2 では、対応機器を同じ Child Bridge から Matter アクセサリとして公開することもできます。

設定ファイルを手作業で編集しなくても、Amazon 認証、機器の取得、公開対象の選択まで Homebridge の設定画面で進められます。

[English](README.md) | [今後の予定](ROADMAP.md)

## 作成した背景

開発に使用した日本の`amazon.co.jp`環境では、Alexa の認証セッションが約 1 日後に利用できなくなり、手動での再認証が必要になる事象を確認しました。また、認証後に利用可能な機器名を設定画面へ自動反映し、公開対象を画面上で選びたいという目的もありました。

そこで本プラグインでは、認証状態を設定画面で確認できること、保存済みセッションを可能な範囲で自動更新すること、更新できない場合はブラウザ再認証へ分かりやすく誘導することを重視しています。

セッションの有効期間は Amazon 側の仕様、アカウント、地域、認証条件によって変わる可能性があります。「約 1 日」は本開発環境で観測した事例であり、すべての`amazon.co.jp`アカウントに共通する保証値ではありません。

## このプラグインでできること

設定画面から Amazon へ接続すると、Alexa アカウントに登録されている機器と定型アクションを取得します。取得結果は検索や種類表示で絞り込み、HomeKit へ出したい項目だけを選択できます。

- Alexa 機器の自動取得と再取得
- 機器名検索、種類表示、表示中項目の一括選択
- 同じ名前の Alexa 機器を内部 ID で区別して個別選択
- Alexa 側の名称を変更しない HomeKit 専用の別名
- 日本語／英語の設定画面と表示言語の自動判定
- 認証状態、取得処理、完了結果の画面内表示
- 物理操作や別リモコンによる変更を検出する定期状態確認（初期値は有効）
- Alexa 定型アクションを一時的な HomeKit スイッチとして実行
- 未知の機器でも ON/OFF 操作が確認できればスイッチとして公開
- Homebridge 2 で照明、ロック、コンセント、スイッチを Matter へ任意公開
- Kokochi Pilot 向け Local Context API（任意、有効時も Bearer 認証必須）

## Kokochi Pilot Local Context API

連携設定欄は、同じHomebridge環境に `homebridge-kokochi-pilot` がインストールされている場合に表示されます。

Local Context API は初期状態では無効で、常に`127.0.0.1`だけで待ち受けます。LAN アドレスへ公開する設定はありません。API 受信用とイベント送信用に別々の Bearer トークンを自動生成し、プラグインの persist 領域へモード`0600`で保存します。詳細設定で各トークンを明示指定することもできます。

ベース URL は既定で`http://127.0.0.1:40321`です。すべてのリクエストに`Authorization: Bearer <apiToken>`を付けます。

- `GET /health`：API 稼働状態
- `GET /v1/context`：公開対象機器、能力、共有状態キャッシュのスナップショット
- `GET /v1/devices`：公開対象機器の一覧
- `GET /v1/devices/{id}`：1 台分の情報と状態
- `GET /v1/devices/{id}/state`：`observedAt`、`stale`、`stateConfidence`を含む共通 Snapshot
- `GET /v1/devices/{id}/capabilities`：共通 Capability
- `GET /v1/info`：実装バージョンと対応範囲
- `PATCH /v1/devices/{id}/state`：エアコン操作。必須の`operationId`、`controlContext`、`changes`を指定。鍵は読み取り専用

初期対象はエアコン、鍵、温度、湿度です。操作後は Alexa 状態を再取得し、要求と一致した場合だけ`confirmed: true`を返します。コマンドから推定した値で共有キャッシュを書き換えることはありません。イベント URL を設定すると、確認済み操作と状態差分をイベント送信用トークンで通知し、Local Context 操作に紐付かない変化は`external-or-unknown`として送信します。

API は Alexa 認証セッションを新たに作りません。既存の検出フィルター後の機器だけを公開し、状態キャッシュと定期確認を共用します。操作も既存の Alexa API ラッパーを通るため、HomeKit/Matter の変換経路には変更を加えません。

## はじめて使うとき

### 1. Amazon へ接続

Homebridge UI でプラグイン設定を開きます。日本のアカウントでは Amazon ドメインに`amazon.co.jp`を選び、ブラウザから到達できる Homebridge のホスト名または IP アドレスを指定します。

認証プロキシのポートには、ほかのサービスが使用していない番号を設定してください。

`Alexaに接続`を押すと Amazon のログイン画面が開きます。ログイン、MFA、CAPTCHA、端末承認など、表示された確認を完了してください。認証完了ページが表示されたら、そのページを閉じて Homebridge の設定画面へ戻ります。

設定画面を開くと、保存済みセッションを Alexa へ接続して確認します。期限切れの場合は Amazon アカウント欄に`期限切れ`と表示し、`Alexaに接続`の再実行を案内します。一時的な Alexa 側の障害や通信障害は期限切れと分けて表示し、保存済みセッションを削除しません。

### 2. HomeKit へ出す機器を選択

`機器を再取得`を押すと、Alexa から機器と定型アクションを取得します。通信に時間がかかっても設定画面は操作でき、完了後に一覧が更新されます。

一覧から公開対象を選択し、必要に応じて HomeKit 用の別名を設定します。

### 3. 保存して反映

設定を保存して Child Bridge を再起動します。選択した機器が Apple のホームアプリへ追加されます。

## HomeKit への変換

Alexa が報告する種類と操作能力を見て、適切な HomeKit アクセサリへ変換します。

| Alexa 側の機器                  | HomeKit での表示     | 主な操作                               |
| ------------------------------- | -------------------- | -------------------------------------- |
| 照明                            | ライト               | 電源、明るさ、色温度、対応機器のカラー |
| スマートロック                  | ロック               | 施錠、解錠、状態取得                   |
| コンセント／プラグ              | コンセント           | 電源                                   |
| スイッチ                        | スイッチまたはライト | 電源、対応機器の明るさ                 |
| ファン                          | ファン               | 電源、対応機器の速度                   |
| サーモスタット                  | サーモスタット       | 温度と運転モード                       |
| 温度／湿度／空気質／CO センサー | 各種センサー         | 状態取得                               |
| Alexa 定型アクション            | 一時スイッチ         | 定型アクションの実行                   |

Alexa 連携先やアカウントによって公開される操作能力が異なるため、同じ製品でも利用できる項目が変わる場合があります。

## Matter 対応（Homebridge 2）

Matter 対応は、HomeKit 側ですでに利用している Alexa 認証、検出済み機器、操作処理、状態キャッシュをそのまま再利用します。Amazon セッションや定期ポーリングを Matter 用に重複して作成することはありません。

### Matter を有効にする手順

すでに Alexa 認証と HomeKit へ公開する機器の選択を完了している場合、その設定を Matter でも共用するため、認証や機器選択をやり直す必要はありません。初期設定がまだの場合のみ、先に Alexa 認証、機器選択、設定保存を完了してください。

1. Homebridge UI で Alexa Smart Home Plus の Child Bridge に Matter を有効化します。
2. Child Bridge を再起動します。
3. Homebridge に表示される Matter のコミッショニング情報に従い、対応する Matter コントローラへ追加します。

選択済み機器のうち対応するものが自動的に登録されます。Matter でも HomeKit と同じ公開対象と HomeKit 用の別名を使用するため、Alexa 機器を別の一覧で選び直す必要はありません。

| Alexa 側の能力               | Matter での種類        |
| ---------------------------- | ---------------------- |
| 電源のみの照明               | On/Off Light           |
| 調光／色温度／カラー対応照明 | 対応能力に応じた Light |
| スマートロック               | Door Lock              |
| スマートプラグ               | On/Off Plug-in Unit    |
| その他の安全な電源操作機器   | On/Off Switch          |

Alexa が対応能力を報告している場合、電源、明るさ、色温度、カラー、施錠・解錠を Matter から操作できます。状態更新には既存の Alexa 状態キャッシュと定期状態確認を共用します。

Homebridge 1 では従来の HomeKit アクセサリだけを公開し、Matter レイヤーは自動的に使用しません。Matter のペアリングやコントローラ側の対応状況は、Homebridge 2 と利用する Matter 環境に依存します。センサー、サーモスタット、ファン、Alexa 定型アクション、カメラ、Alexa 固有機能の Matter 変換は現時点では未対応です。同じ実機を HomeKit と Matter の両方から公開すると、両方の経路を取り込む環境では二重に見える場合があります。利用するコントローラに合わせて公開経路を選択してください。

### 定期状態確認

Alexa 連携機器の中には、物理操作や別のリモコンで状態が変わってもイベントを通知しない機器があります。定期状態確認を有効にすると、10 秒後、15 秒後、30 秒後、1 分後、3 分後、5 分後、10 分後、15 分後に状態を取得し、その後は設定した間隔で継続します。定常時の初期値は 5 分で、1、3、5、10、15、30 分から選べます。HomeKit から操作した場合はスケジュールを先頭から再開します。複数機器への問い合わせは分散され、一時障害時は最大 60 分まで間隔を自動的に延長します。

Alexa が状態取得に対応していない機器や古い値を返す機器もあります。該当する機器は、HomeKit や Matter の表示と実機の状態が異なる場合があります。定期状態確認は Alexa が返した状態を反映する機能であり、Alexa 側で更新されていない状態を強制的に再取得するものではありません。

### 実機で確認した構成

- Qrio Lock：施錠、解錠、現在状態
- Alexa 登録照明：電源、明るさ、色温度、現在状態

## 認証情報とプライバシー

Amazon のユーザー ID、パスワード、MFA コードをプラグイン設定へ入力する欄はありません。これらは Amazon が表示するログインページへ入力され、このプラグインは保存しません。

認証後は、Alexa へ継続接続するためのセッション情報だけを Homebridge の`persist`領域に保存します。更新可能な間はセッションを自動更新し、再認証が必要になった場合は設定画面に接続操作を案内します。

未認証で起動したChild Bridgeは、設定画面で認証情報が保存されると接続を開始します。認証待ちからの接続にHomebridgeの再起動は不要です。

## 困ったときの確認場所

### Amazon の画面が開かない

- 認証に使う Homebridge ホストが、操作中のブラウザから開けるか確認します。
- 認証プロキシのポートが別サービスと重複していないか確認します。
- Homebridge を別端末やコンテナで動かしている場合は、その端末へ到達できるアドレスを使います。

### 機器取得が終わらない、または一覧が空

- Alexa アプリで対象機器を操作できるか確認します。
- 接続済み表示を確認してから`機器を再取得`を押します。
- 取得中でも画面を操作できます。少し待ってからもう一度取得できます。

### 保存した機器がホームアプリにない

- 公開対象にチェックが入っているか確認します。
- 設定保存後に Alexa Smart Home Plus の Child Bridge を再起動します。
- センサーはアクセサリタイルではなく、部屋上部の状態欄に表示されることがあります。

## 対応環境

- HomeKit は Homebridge 1.x／2.x、Matter は Homebridge 2.1.1 以降
- Node.js 18／20／22／24
- Homebridge Config UI X を利用した初期設定を推奨

## 開発時の確認

```bash
npm ci
npm run verify
npm run verify:release-target
npm pack --dry-run --ignore-scripts
```

`verify`は単体テスト、Lint、TypeScript ビルドを順番に実行します。Amazon アカウントが必要な実機テストは通常の単体テストから分離しています。

公開先確認では、npm パッケージのリポジトリ情報、`origin`の push URL、現在のブランチの追跡先、任意で登録した`upstream`が取得専用になっていることを検査します。共有 pre-push フックは`sylpied/homebridge-alexa-smarthome-plus`以外への push を拒否します。開発用チェックアウトでは`git config core.hooksPath .husky`を設定してフックを有効にしてください。

## プロジェクトについて

Amazon が公開していない連携方式を使用する依存ライブラリがあるため、Amazon 側の変更によって一時的に認証や操作が利用できなくなる可能性があります。本プロジェクトは Amazon および機器メーカーの公式製品ではありません。

本プロジェクトは MIT ライセンスの`joeyhage/homebridge-alexa-smarthome`を出発点とし、独自のパッケージ名、プラットフォーム名、設定画面、認証導線、機器選択機能を持つ派生プロジェクトです。元プロジェクトの README 文章は転載していません。両方のプラグインで同じ機器を公開すると、HomeKit に重複して表示されます。
